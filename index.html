Under the hood

Memory contract: preferences.json → training-pack.json

Two artifacts, two jobs. preferences.json is raw training data — every swipe, metadata, correction notes. training-pack.json is the agent-facing memory: a compact, curated artifact your agent reads at runtime.

The agent never has to ingest a noisy swipe log. Lossy compression in the right direction: ~12 diverse examples plus stable rules, not 500 raw decisions. MCP (watch-preferences.py) exposes only the distilled pack.

Compiler: swipes → domain model

analyze-preferences.py compiles behavior into abstractions, not just stored history:

  • Diverse few-shot examples (select_diverse_examples())
  • Sender / domain patterns from grouped swipes
  • Needs Attention watch rules → agent-watchlist.json
  • Safe label candidates → platform-rules.json (inbox preserved)
  • Folder proposals → folder-suggestions.json

Not brittle prompt stuffing — a small domain model compiled from user behavior.

Truthful memory + captured uncertainty

Examples store the user's actual decision and optional correction note — no fabricated post-hoc reasoning. Mixed decisions on the same sender become inconsistentSenders, which is a better signal for an agent than pretending every pattern is clean.

runtimeGuidance ships alongside memory: token budget advice, never auto-delete, never skip inbox without approval. Memory encodes what you like and how the agent must behave safely.

Active-learning queue

orderEmailQueue() in app.js scores mail by uncertainty and urgency — not chronological order. Prior swipes by domain plus keyword hints push the next best training example to the front.

Inline hints calibrate trust: “Similar to 3 you marked spam” when confidence is high; “Help me learn this one” when it's fuzzy. Batch spam only offers after you manually spam one, siblings share the domain, and the model would guess spam independently — earned shortcut, not reckless automation.

Victory screen = correction loop

Session end isn't just polish. The victory screen shows pile breakdown, grades scorable predictions, surfaces misses, and captures correction notes — review at the moment you still have context. That feedback feeds better training on the next compile.

Human-in-the-loop automation

Platform rules are suggest_only: labels and stars are fine; skipping the inbox is not. Needs Attention is agent-managed reasoning, not a hidden Gmail filter. Helpful automation without silent control loss.

Runtime: metadata fetch → local rule match from platform-rules.json (no LLM) → watchlist pre-filter → LLM only for remaining ambiguous candidates.

Architecture layers
  • UI — captures actions; IndexedDB locally; serve-ui.py → ~/.config/email-swipe/preferences.json
  • Compiler — import-preferences.py / analyze-preferences.py derives memory
  • MCP — get_training_pack, get_watch_rules; agent sees distilled artifact only

baseline-predictions.js gives heuristic predictions from email #1; learned behavior takes over as swipes accumulate. Export falls back to download if local save isn't available; compiler runs from preferences if the pack doesn't exist yet. Graceful degradation across paths.
